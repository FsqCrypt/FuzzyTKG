# 2026-09-17 TKG 创新点与全流程链路总览

> 本文档固化 TKG 转向后的创新点全貌与完整链路,作为**当前状态的单一事实来源**。
> 背景:TKG 的设计此前散落在三处——`claude.md`(2400 行实验记录)、`tkg-transition.md`(选型论证)、
> `Innovation.md`(静态 KG 措辞)——需要跨文件拼接才能还原完整思路,且措辞存在静态/时态混用。
> 本文档统一为 TKG 语言,并标注每个创新点的**证据等级**(已证 / 未证 / 已证伪)。

## 一、出发点:原始 FuzzSys 的两个结构缺陷

FuzzSys-CQA 的原始链路:

```text
LP score → membership function → fuzzy rule base → defuzzification → answer ranking
```

它比 CQD/QTO 的传统 fuzzy set operation 更灵活,尤其改善了含 negation 的复杂查询。但仍有两个未解决的限制:

```text
缺陷 1:所有 relation 共用同一条全局 membership 曲线;
缺陷 2:所有 query context 共用同一套固定 fuzzy rule 参数。
```

**这两个缺陷是全部创新点的源头。** 整体目标是把:

```text
全局二值 membership + 静态 fuzzy rules
```

扩展为:

```text
关系感知三值 membership + 查询上下文自适应 fuzzy rules
```

## 二、为什么是 TKG:转向动机

| # | 动机 | 说明 |
|---|---|---|
| 1 | **时态引入新的分数不可比维度** | 静态问题是"不同 relation 分数不可比";TKG 额外叠加"同一 relation 跨时间段也不可比"(稀疏期普遍低分、密集期普遍高分)。原校准创新点自动升级,价值变大 |
| 2 | **查询计划优化在时态下更扎实** | 时间约束天然产生选择性差异——`1p(h, r, ?, 1990)` 可能只剩 500 个候选,2020 年有 8000 个。数据库"谓词下推 / 驱动表选择"的类比完全成立 |
| 3 | **竞争少** | 静态 CQA 社区成熟(CQD/QTO/BetaE/FuzzSys),时态 CQA 尚在早期 |
| 4 | **TFLEX 已铺路** | 时态版模糊逻辑 CQA 已存在(NeurIPS 2023),数据集、查询集、评测协议全部公开,直接对接 |

转向决定见 `claude.md` Session 12(2026-08-15),选型论证见 `tkg-transition.md`。

## 三、创新点全貌

### 3.1 创新点 1(主线):跨 (relation, time_bucket) 分数可比性校准

**问题发现(论文叙事的核心)**:

> CQA 中不同 relation 的 LP 分数天然不在同一量尺上——同一绝对分数值在简单高频 relation 和稀疏困难 relation 中含义截然不同。
> 而 `max` / `min` / `product` 等模糊算子在数学上**要求 operand 可比**,现有方法从未质疑这个前提。
> 时态进一步叠加第二层不可比:同一 relation 跨时间段的分数也漂移。

**方法(两层校准框架,即插即用)**:

```text
Layer 1  Score-Shift        — 在模糊算子之前,做 per-(relation, time_bucket) 分支级分数偏移
Layer 2  Fractional Penalty — 在 B-spline 之后,做不确定性感知的三值分解
```

**静态版 → 时态版的映射**:

| | 静态版 | TKG 版 |
|---|---|---|
| 校准键 | `relation` | **`(relation, time_bucket)`** |
| Layer 1 | per-relation Score-Shift | per-(relation, time_bucket) Score-Shift |
| Layer 2 | 三值 Fractional Penalty | **机制零改动**,offset 与 β 在新 LP 分数分布上重拟合 |
| 代码改动 | — | 集中在 `compute_rel_stats.py` 分组维度 +1 与 shift 查表 |

**关键性质**:机制完全复用,唯一升级是统计量的分组键。文档明确"这是唯一需要代码改动的创新点"。

**时态桶划分**:无先验,先用分数漂移测量(同一 relation 跨时间段 τ_s 漂移幅度)决定桶宽,再定桶数。

### 3.2 创新点 2:查询结构感知与自适应模糊规则

把固定的模糊规则参数 `ALPHA_I / ALPHA_U / ALPHA_N` 改成 `f(query_context)`。

```text
ALPHA_I = f(query_context)
ALPHA_U = f(query_context)
ALPHA_N = f(query_context)
```

**时态带来的变化**:

| | 静态版 | TKG 版 |
|---|---|---|
| 题型数 | 14 类 | **40 类**(ICEWS14 本地含 2 个额外题型,共 42) |
| 答案类型 | 只有实体 | **实体 + 时间戳**两条路 |
| 新题型家族 | — | `Pt` / `aPt` / `bPt` / `between` / `t2i` / `t3i` 等 |
| 新增算子 | — | **after / before / between**(模糊语义需自行设计) |

**上下文特征**(第一版,轻量可解释,避免直接上 MLP):

```text
query_type            题型标识
boundary_mass         Boundary 隶属度均值或 top-k 均值
strong_mass / weak_mass
score_gap             top1 score − top-k mean score
score_entropy         top-k 分数分布熵
conflict              多子查询分数差异 / top-k 候选冲突程度
negated_boundary_mass 被否定子查询中的 Boundary 比例
```

**规则设计**:

- **交集**:`boundary_mass` 高 → `alpha_I` 增大 → 更接近严格 min → 更保守;`conflict` 高同样增大
- **否定**:`penalty = p_s·μ_S + p_b·μ_B + p_w·μ_W`,其中 `p_s > p_b > p_w`;主查询本身 Weak 时不允许 NOT 单独抬高实体

### 3.3 创新点 3(升格·主创新):时态查询计划优化

**理论贡献**——时间约束在模糊 CQA 中是**不可交换算子**:

```text
Plan A: 先模糊交集,再对结果施加时间约束
Plan B: 每个分支先施加时间约束,再做模糊交集

SQL 中两计划等价(谓词下推保语义);
模糊 CQA 中不等价:时间约束改变分数分布 → 改变 B-spline 隶属 → 改变 fuzzy intersection 结果。
```

**方法贡献**——基于 (relation, time) 选择性的计划选择器。

**类比**——数据库谓词下推 + 驱动表选择,reviewer 一听就懂。

### 3.4 论文的三层贡献结构

```text
贡献 1  问题发现(Finding)  — 分数不可比,模糊算子的隐含前提被违反
贡献 2  校准方法(Method)   — 两层校准框架,即插即用,无需重训 LP
贡献 3  边界分析(Analysis) — 不同算子的收益幅度由其数学结构决定
```

**贡献 3 是叙事的精髓**:把"intersection 没提升"从"方法不够好"重新定义为"数学结构决定的边界"——
弱点变成 insight,并自然指向创新点 2 的必要性。

### 3.5 差异化定位(对 TFLEX)

TFLEX(NeurIPS 2023)证明了模糊逻辑能处理时态查询,但它**没有**:

- ❌ per-relation / per-(relation, time) 校准(分数不可比问题)
- ❌ 三值 Fractional Penalty
- ❌ 查询计划选择(时间约束放在哪一步)

**附加卖点**:我们是**冻结 LP + 零训练成本的即插即用校准**,对比 TFLEX 的 20 万步端到端训练——
"training-free adaptation"本身就是一层差异化。且同一套校准从 TComPlEx → TNTComplEx 自动重拟合,
是天然的鲁棒性实验(双 LP 报告策略)。

### 3.6 原创新点在 TKG 下的重新定位

**结论:两个原创新点(关系感知、查询结构感知)都完整保留,但地位发生对调。**

| 原创新点 | TKG 下的状态 | 变化 |
|---|---|---|
| 关系感知(分数可比性校准) | 机制 100% 复用,动机更强,但**收益面受算子结构限制** | 地位不变,天花板已知 |
| 查询结构感知(自适应模糊规则) | **从"补充"升级为"必须"** | **地位上升** |

#### 3.6.1 关系感知:机制没变,但有两个未验证的前提

**前提 1——时间漂移是否真的存在?**

TComPlEx 的 `w_τ` 时间嵌入**本身就在吸收一部分时间效应**。有可能它已经把
"稀疏期分数普遍偏低"这类漂移补偿掉了,那么"跨时间不可比"这个动机在**查询输出分数**上就不成立。

> ⚠ **测量口径**:必须在**查询输出的分数**上测漂移,**不能拿原始四元组分数测**——
> 后者必然有漂移,但那部分已经被 `w_τ` 吃掉了。对应风险 C(见第九节)。

**前提 2——收益面受限于算子结构。**

静态阶段已用实验证明杠杆度由算子数学结构决定:

```text
negation      membership 直接控制实体生存   →  极高杠杆(+13.2%)
union         max 的选择被修正              →  中等(+2.5%)
intersection  soft-min 是单调变换           →  结构免疫(~0%)
```

TKG 用的是同一套 soft-min,**这个免疫大概率会重现**。这不是缺陷,应写成"边界分析"贡献。

#### 3.6.2 查询结构感知:地位上升的三个理由

**理由 1——题型从 14 类扩到 40 类(近 3 倍)。**
静态时 14 类已需分组,40 类下靠一套固定 `alpha` 更不现实。

**理由 2——多了一条全新的答案模态。**
静态只有"答案是实体";TKG 新增"答案是时间戳"的题型家族
(`Pt` / `aPt` / `bPt` / `between` / `t2i` / `t3i`)。两类题型的分数分布性质完全不同——
实体候选 7128 个、时间候选仅 365 个(ICEWS14),且时间题型的平均答案数达 120~2000
(论文自身也只有 3 分)。同一套 `alpha` 无法适配两种分布。

**理由 3(最关键)——静态阶段已经把话说到位了。**

`Innovation.md` 原话:

> Intersection 需要的是**算子本身 relation-aware**(`alpha = f(relation)`),而非分数校准。这恰好连接模块二。

即:**静态 11 个 Session 的实验已经证明"创新点 1 撞到天花板",而天花板之外的唯一出口就是创新点 2**。
TKG 中 intersection 类题型(`e2i` / `e3i` / 各 `_N` 变体 / `t2i` / `t3i`)在 40 类里占比很大——
对出口的需求比静态时更大。

#### 3.6.3 TKG 生长出的新维度

原创新点在时态场景下**自然生长出**一层新内容(静态 KG 中不存在):

```text
静态:  alpha = f(query_type, relation_reliability)
TKG :  alpha = f(query_type, relation_reliability, time_bucket)
```

**稀疏时段的判断更不可靠 → `alpha` 应更保守。**

这与创新点 1 形成呼应:**时间桶既影响分数可比性(创新点 1),也影响算子保守度(创新点 2)**。

#### 3.6.4 两个创新点的分工关系

```text
                    TKG 的 40 类题型
                          │
        ┌─────────────────┴─────────────────┐
        │                                   │
   否定类 / 并集类 / 链式类            交集类 / 时间类
        │                                   │
        ↓                                   ↓
   ┌─────────────┐                   ┌─────────────┐
   │  关系感知    │  ← 有效           │  关系感知    │  ← 结构免疫
   │ (创新点 1)   │                   │   (无效)     │
   └─────────────┘                   └──────┬──────┘
                                            │
                                            ↓
                                     ┌─────────────┐
                                     │ 查询结构感知 │  ← 唯一出口
                                     │  (创新点 2)  │
                                     └─────────────┘
```

**它们不是"两个独立的创新",而是"同一个问题(relation / time diversity)在两个层面
(分数空间 vs 算子空间)上的完整解决方案"。** 这一定位在 `Innovation.md` 中已写好,可直接沿用。

#### 3.6.5 携带资产:三条死路结论直接迁移

静态阶段的试错结论**是纯数学性质,与数据无关**,在 TKG 下同样成立,无需重做:

```text
❌ 线性分数归一化     →  ~0%(单调变换保排序,数学上无效)
❌ B-spline 前移      →  -7.5%(压缩分数尺度,soft-min 失去区分力)
❌ 硬阈值截断         →  -3 ~ -5%(破坏分数分布,max/min 选择错误)

✅ 结论:改算子参数,不改算子输入
```

这三条可直接写进论文的"我们试过了"部分(见第八节)。

#### 3.6.6 一个必须正视的事实

**创新点 2 至今零代码、零实验。** 静态阶段在 Session 11 提出后即转向 TKG。

这意味着:论文中**唯一被证明有效的机制是创新点 1**,而**创新点 2 承担了"突破创新点 1 天花板"的全部期望**。
若创新点 2 也失败,TKG 版的收益面将只剩否定类与链式类。

→ 因此**创新点 2 的优先级应提升至与创新点 1 并列**,而非作为 Phase 2 的补充项。

## 五、TKG 特有的技术难点

| 难点 | 内容 | 处理 |
|---|---|---|
| **时间候选空间** | `Pt`/`aPt`/`bPt`/`between` 的答案是时间戳(365 / 4017 / 366 个候选),不是实体 | LP 打分模块须**同时输出 [B, N] 与 [B, T]** |
| **列类型映射** | 每列是实体/关系/时间戳因题型而异 | 以各题型的 `args`(`query_name_to_args`)为唯一权威 |
| **时间算子语义** | `after` / `before` / `between` 的模糊语义无现成答案 | **Phase 2 研究性工作**,先做实体侧题型 |
| **归一化重验** | TComPlEx 复数内积分数的幅值范围与 ComplEx 不同 | 冒烟测试中检查 B-spline 输入分布,必要时调整归一化 |
| **数据量级** | GDELT 2211 万查询(ICEWS14 的 20 倍) | 采样评测 + 完整评测双轨 |

**⚠ 两处必须注意的发现**:

1. **论文实际是 40 类题型,不是 42 类**。论文 Table 6 的查询结构定义逐条数下来是 40 类;
   `baseline_tflex_icews14.md` 中 AVG 行标注的"全部 42 类"**有误**(该表自身也只列了 40 行)。
2. **论文 AVG 是宏平均**。用 `third_party/TFLEX/assets/table2_full_results.tex` 原始数值反推:
   `AVG 35.93` = 7 个组均值的平均(宏平均);40 个题型直接平均为 `33.72`(微平均)。
   论文 table2 标题 "AVG denotes average performance under all query types" 表述有歧义,**以数字为准**。
   报告我们自己的 AVG 时必须用同一口径,否则会产生约 2.2 分的无意义差距。

3. **本地 ICEWS14 比官方表多 2 个题型**:`Pe_nPt`、`Pe_nt2i`(TFLEX 生成代码中这两行被注释掉,
   `ComplexTemporalQueryData.py:854,861,891,898`)。ICEWS14 三个 split 均有(14564 / 7540 / 8416 条);
   ICEWS05-15 仅 train 有(73792 条)。**评测时须以论文的 40 类为准做对齐**,这 2 类不计入平均分。

| 1 Layer 1(Score-Shift) | ✅ 部分:negation **+13.2%**、chain(ip/up/inp) +2–3%、**intersection ~0%**、union +2.5% | ❌ **零** |
| 1 Layer 2(三值 Fractional Penalty) | ✅ up +2.5%、3in H@3 **+15.9%** | ❌ **零** |
| 2(查询结构感知 / 自适应规则) | ❌ **从未实现**(Session 11 提出后即转向 TKG) | ❌ **零** |
| 3(计划优化) | ❌ 纯概念,连"计划空间是否存在"都未验证 | ❌ **零** |

**已提炼的理论洞察(静态阶段最重要的产出)**:

> 收益幅度**不取决于方法好坏,而取决于算子本身的数学结构对分数校准的敏感度**。
>
> | 算子 | 机制 | 杠杆度 |
> |---|---|---|
> | Negation | membership 直接控制实体生存 | 极高(+13.2%) |
> | Union | max 的选择被修正 | 中等(+2.5%) |
> | Intersection | soft-min 是单调变换,保持实体排序 | **结构免疫(~0%)** |

## 八、已排除的死路(可直接写进论文)

静态阶段用实验排除了两条路径,**任何在 max/min 之前改变分数值的操作都是有害的**:

| 尝试 | 结果 | 根因 |
|---|---|---|
| Per-Cluster B-spline 前移 | **−7.5%** | membership 空间压缩分数尺度,soft-min 后失去区分力 |
| Per-Cluster 硬阈值截断 | **−3 ~ −5%** | 硬截断破坏分数分布信息,max/min 选择错误 |
| 线性 score 归一化 | ~0% | 单调变换保持排序,数学上无效 |

**结论**:突破方向应为改变**算子参数**(alpha),而非算子**输入分数**——这直接指向创新点 2。

## 九、结构性风险与开放问题

| # | 风险 | 说明 | 应对 |
|---|---|---|---|
| A | **创新点 2 是命门,却从未实现** | 静态已证 intersection 对校准结构免疫。TKG 大概率是同一套 soft-min,同样免疫会出现——那么创新点 1 的收益面只剩否定类与链式类,创新点 2 从"补充"变成"必须成立" | 将创新点 2 提到与创新点 1 **并列**的优先级,而非当作补充 |
| B | **主创新(计划优化)最脆弱** | 被标为"主创新",但"计划空间是否存在"从未验证;TFLEX 查询结构由题型固定,"替代计划"需先精确化 | **先做 Oracle 实验测上限**,上限不够则降格为分析性贡献,不投入工程 |
| C | 时间漂移动机未验证 | "同一 relation 跨时间分数漂移"目前是**假设**,不是证据 | 用对齐好的 TComPlEx 在**查询输出分数**上测漂移(注意 `w_τ` 已吸收部分时间效应,不能测原始四元组分数) |
| D | LP 强度未知 | TComPlEx 在 CQA 协议下若远低于 TFLEX,绝对数字站位会很难看 | **Phase 0 的决策闸门**:Pe 冒烟对照论文 48.21 |
| E | 协议实现风险 | easy-answer mask 实现错误会导致数字虚高(领域公认作弊) | 冒烟测试第一天就把协议写对 |
| F | 时间桶粒度无先验 | 桶宽决定校准粒度 | 先测漂移幅度再定桶数 |

## 十一、论文表述边界

**不要声称**:

```text
❌ 首次做 fuzzy CQA
❌ 首次做 CQA calibration
❌ 首次做 adaptive operator
❌ 承诺整体 average MRR 大幅提升
```

**稳妥定位**:

> 在 LP-based fuzzy CQA 框架中,针对全局二值 membership 和静态 fuzzy rules 的不足,
> 提出关系感知三值隶属与查询上下文自适应规则(TKG 版叠加时态校准与计划选择),
> 用于改善复合查询尤其是否定查询中的 hard-relevant entity 处理。
