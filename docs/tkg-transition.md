# 2026-08-15 创新点向时态知识图谱的过渡:数据集与 LP 打分器选型

> 承接 claude.md Session 12 的战略决定(全面转向 TKG)。本文档记录两件事的完整论证:
> ① 数据集与 LP 打分器为什么这么选;② claude.md 提出的创新点如何从普通 KG 过渡到时态 KG,以及后续与时态相关的衔接安排。

## 一、选型总览

| 决策项 | 结论 | 一句话理由 |
|---|---|---|
| 数据集 | TFLEX 三数据集全上(ICEWS14 主 / ICEWS05-15 泛化 / GDELT-500 补强) | 时态 CQA 领域唯一的标准基准,数据少则方法无说服力 |
| LP 打分器(现在) | TComPlEx(ICLR 2020),现成权重已 100% 对齐 TFLEX ID 空间 | 与 ComplEx 同族的时态扩展,替换成本最低、零训练成本 |
| LP 打分器(GPU 到位后) | TNTComplEx(ICLR 2020)自训,作为第二实验条件 | 同族公式 +8~9 点 MRR;双 LP 报告兼顾公平性与上界 |
| 判卷协议 | 严格遵循 TFLEX 协议(easy answer 排除 + hard answer MRR) | 不遵循数字虚高且无意义,违背领域共识 |

## 二、数据集选型

### 2.1 为什么是 TFLEX 三数据集

- TFLEX(NeurIPS 2023)是时态复杂查询嵌入领域的首个框架,其发布的三数据集是**该领域目前唯一的标准基准**,查询集、评测协议、词汇表全部公开。
- 用户明确要求数据集不能太少,否则方法缺乏说服力 → 三数据集全上:
  - **ICEWS14(主战场)**:7128 实体 / 230 关系 / 365 时间戳,查询 108.9 万(42 类题型);论文基线数字最全(Table 14 逐题型 MRR)。
  - **ICEWS05-15(泛化验证)**:10,488 实体 / 251 关系 / 4017 时间戳,查询 472.6 万,规模与难度更高。
  - **GDELT-500(补强)**:500 实体 / 20 关系 / 366 时间戳,查询 2211.7 万(ICEWS14 的 20 倍),40 类题型。

### 2.2 数据集构成:四元组是"教材",查询是"考题"

- **四元组**(train/valid/test 事实表)是 LP 打分器的训练材料,划分沿用 Garcia-Duran et al. (EMNLP 2018) 的领域标准划分——不是 TFLEX 自己发明。
- **查询**(42 类模板 × 3 划分的题目+答案)是评测场地,由四元组通过 subgraph matching 自动出题;同一个事实可以产生多个方向的题(Pe 问实体、Pt 问时间戳)。
- **ID 空间注意**:实体 / 关系 / 时间戳是三套独立 ID,同一数字在不同题型列中含义不同,执行查询时必须以各题型的 `query_name_to_args` 为准判断每列类型。

### 2.3 数据集"公平性"核查结论:无手脚

逐项核对了论文 Appendix B.2/B.5 与采样、评测代码(`ComplexTemporalQueryData.py`、`main_TCQE_TFLEX.py`):

- 四元组划分为领域公共资产,查询生成纯事实驱动、不经过他们的模型;
- 逆向/双向采样只保证答案集非空,不降低难度;
- 8 类题型(avg{Ue}/avg{Ut}/avgx)故意零训练样本,考未见结构的泛化,对可训练方法更苛刻;
- aPt/bPt/between 平均答案数 120~2000,答案集巨大,MRR 天然被压低(他们自己也只拿 ~3 分);
- 三个非致命瑕疵(均不偏向任何方法):① 拒绝重抽使测试集是"可答题"的有偏样本(业界通行做法);② 每题型 valid/test 上限 1 万条;③ 继承的随机划分带来时间戳重叠(对所有方法一致,可写入 threat-to-validity 主动披露)。

### 2.4 判卷协议:必须遵循

TFLEX 协议(Appendix B.5):答案集 = JqK_test − JqK_valid(hard answers);排序时 easy answers(训练/验证图可推出的答案)全部 mask 为 -inf;MRR 在全部实体/时间戳候选上计算。

- 若不遵循(如把 easy answers 计入分数),数字会大幅虚高(单跳题型可从 ~40 飙到 60-80+),因为 LP 对训练见过的四元组有强记忆效应——这是领域公认的作弊,审稿人必查,风险是论文被拒。
- **注意**:已下载的 jsonl 中 `answer` 字段是 JqK_test(含 easy answers),评测时必须用四元组文件重新推导 easy/hard 划分,或直接复用 TFLEX 评测代码算排名。

## 三、LP 打分器选型

### 3.1 约束条件

- 接口:必须输出 [B, N] 分数矩阵(系统其余部分零改动的前提);
- 公平性:打分器越强,与 TFLEX 的对比越需要披露与消融;
- 现实:本机当前无 GPU(1 核 CPU),GPU 稍后到位。

### 3.2 候选对比

| 模型 | ICEWS14 MRR | 公开权重 | 与 ComplEx 同族 | 备注 |
|---|---|---|---|---|
| TTransE / HyTE | 25.5 / 29.7 | — | 否 | 已过时 |
| **TComPlEx** | **~0.52-0.56** | **有(已对齐)** | **是(时间 Hadamard 扩展)** | 首选 |
| DE-SimplE | 52.6 | 无 | 否 | 同级但无权重 |
| **TNTComplEx** | **60.7** | 无,需自训(官方代码 tkbc) | 是 | GPU 到位后升级 |
| ChronoR | 62.5 | 无 | 否(旋转式) | 更强但接口不同、无代码资产 |

### 3.3 选定 TComPlEx 的理由

1. **替换成本最低**:现有系统 LP 是 ComplEx,TComPlEx 公式 `score(h, r, t, τ) = Re(⟨h ⊙ r ⊙ w_τ, conj(t)⟩)` 只多一项时间嵌入的 Hadamard 乘积,下游 [B, N] 接口不变。
2. **领域标准模型**:TFLEX 自己就用 TComPlEx 做嵌入初始化,用它对标无争议。
3. **零训练成本**:ICEWS14 / ICEWS05-15 公开预训练权重已下载,并通过名字匹配 100% 对齐到 TFLEX ID 空间(`data/tkg/checkpoints/*/`_tflex_ids.pt`),拿来即用。
4. **升级路径清晰**:TNTComplEx 同公式族、同代码库(tkbc),换公式 + 换权重即可,下游零改动。

### 3.4 TNTComplEx:换不换?——双 LP 报告策略

- **理论增益明确**:原子 MRR +8~9 点(0.52→0.61 / 0.58→0.66)。
- **传导有损耗**:TFLEX 论文自身证据表明,LP 质量到 CQA 表现不是 1:1 传导(他们的 Pe 算子仅 TTransE 水平)。且我们的校准创新本来就为"屏蔽 LP 分数缺陷"而设计,LP 变强后校准的边际收益可能部分抵消。
- **公平性风险**:TFLEX 基线用 TComplEx 初始化;我们若用 TNTComplEx 取胜,审稿人会质疑增益来源。
- **结论**:**不二选一,双 LP 报告**。TComPlEx 版本与 TFLEX 论文数字苹果对苹果;TNTComplEx 版本作为上界并展示方法对 LP 强度的鲁棒性。是否升级由 Pe/Pt 冒烟测试数据决定(对照 TFLEX-1p 的 Pe MRR 42.9):若 TComPlEx 已接近,升级优先级降低;若差距明显,升级有直接证据。
- GPU 到位后:用 facebookresearch/tkbc 官方代码训练 ICEWS14 / ICEWS05-15(各约 2-3 小时 GPU);**tkbc 不支持 GDELT**,GDELT 的 LP 需另行自训(500 实体规模小,训练成本低)。

### 3.5 换 LP 对我们方法的影响

- **概念层面零影响**:系统 LP-agnostic,三个创新不依赖具体 LP。
- **参数层面必须重做**:校准统计量(每关系/时间桶均值方差)、三值阈值、归一化策略都是在旧 ComplEx 分数分布上拟合的,TComPlEx 分数分布不同(复数内积,幅值范围不同),必须在新 LP 的分数上重新拟合。
- **这反而是卖点**:同一套校准机制从 ComplEx → TComPlEx → TNTComplEx 自动适应,是天然的鲁棒性实验。

## 四、创新点从普通 KG 到时态 KG 的衔接

claude.md(Session 1-8)沉淀的三个创新点 + Session 12 新升格的一个主创新点,时态衔接分析如下:

### 4.1 创新点 1:跨关系分数可比性校准 → 跨(关系, 时间桶)校准

- **静态版**:不同 relation 的 LP score 不在同一量尺上,在模糊算子(max/min/product)前做分支级 per-relation Shift。
- **时态版**:问题自动放大——同一 relation 在不同时间段的分数也不可比(数据稀疏期普遍低分、密集期普遍高分)。校准键从 `relation` 扩展为 `(relation, time_bucket)`。
- **机制不变,统计量升级**:shift 的估计方式、施加位置(分支级、模糊算子前)全部保留;`compute_rel_stats` 的分组维度加一个时间桶。**这是唯一需要代码改动的创新点,且改动集中在统计脚本与 shift 查询表。**

### 4.2 创新点 2:三值隶属分解(不确定性感知)

- **静态版**:不可靠 relation 的 membership 被折价,μ_B = min(offset_r, m),组合系数 β 随上下文变化。
- **时态版**:机制零改动。时态数据的判断更不可靠(时间维度引入更多尾部事实),三值分解的用武之地更大。
- **衔接要点**:offset 与 β 必须在新 LP 的分数分布上重新拟合;拟合流程不变。

### 4.3 创新点 3:查询结构感知(Query-type scaling)

- **静态版**:按查询类型对分数打折。
- **时态版**:机制不变,题型从 14 种扩展到 42 种,且新增"答案是时间戳"的题型家族(Pt/aPt/bPt/between/t2i…),scaling 的覆盖范围需要按题型重新分组。

### 4.4 新主创新点:时态查询计划优化(时间约束下推不等价性)

- Session 12 升格为主创新点:时间约束在模糊 CQA 中是不可交换算子——先交集后施加时间约束(Plan A)与分支先施加时间约束再交集(Plan B)结果不同(SQL 谓词下推保语义,模糊逻辑不保)。
- 数据库类比(谓词下推 + 驱动表选择)使理论贡献直观可讲;基于 (relation, time) 选择性的计划选择器为方法贡献。
- **风险预案**(Session 12 已记):先用 Oracle 实验验证计划空间的上限收益,再决定投入深度。

### 4.5 时态带来的全新元素(衔接清单)

| 新元素 | 内容 | 处理 |
|---|---|---|
| 时间候选空间 | Pt/aPt/bPt/between 的答案是时间戳(365 / 4017 / 366 个候选),不是实体 | LP 需支持 score_t 方向(h, r, o → 候选时间戳),打分模块同时输出 [B, N] 与 [B, T] |
| 时间算子 after/before/between | 模糊语义无现成答案,需自行设计(ground truth 定义为 t > max(τ) 等) | Phase 2 研究性工作,先做实体侧题型 |
| 列类型映射 | 每列是实体/关系/时间戳因题型而异 | 以各题型的 `query_name_to_args` 为唯一权威,执行器按映射取嵌入 |
| 归一化重验 | TComPlEx 复数内积分数的幅值范围与 ComplEx 不同 | 冒烟测试中检查 B-spline 输入分布,必要时调整归一化 |

## 五、后续衔接计划

### 5.1 近期(无 GPU,立即做)

1. 实现 TComPlEx 打分模块(`src/tcomplex.py`):加载对齐权重,输出 [B, N] / [B, T] 分数矩阵;
2. Pe / Pt 冒烟测试:用 TFLEX 过滤协议算 MRR,同时验证 ID 对齐、打分正确性、归一化合理性;
3. 对照 TFLEX-1p(Pe 42.9)与 TComPlEx 发表值,给出"LP 选取是否合理"的数据结论;
4. Phase 1 适配:Pe/Pt/Pe2/Pe3/e2i/e3i(即 avge 题型组,TFLEX 头号数字 56.79 所在组),创新点 1 的 (relation, time_bucket) 校准随之落地。

### 5.2 GPU 到位后

1. tkbc 训练 TNTComplEx(ICEWS14 + ICEWS05-15),复用对齐脚本,双 LP 报告;
2. 自训 GDELT 的 LP(TComPlEx 即可,模型小);
3. 可选:复现 TFLEX 训练基线(d=800, γ=15, 300k steps,论文 Table 12 超参齐全),作为协议一致性的最终校验。

### 5.3 Phase 2(主线跑通后)

- 否定 / 并集 / 混合题型(机制照搬静态版);
- after/before/between 时间算子的模糊语义设计与实现;
- 时间答案题型的校准与三值适配。

## 六、风险与开放问题

| 风险 | 应对 |
|---|---|
| TComPlEx 打分在 CQA 协议下太弱(Pe 远低于 42.9) | 数据说话:提前到 GPU 到位后训练 TNTComplEx 再定 |
| 时间桶划分粒度无先验 | 先用分数漂移测量决定桶宽(同一关系跨时间段 tau_s 漂移幅度),再定桶数 |
| after/before/between 模糊语义设计失败 | 这三类 TFLEX 自己也只拿 ~3 分,即便暂缓也不影响 avge 主战场结论 |
| GDELT 22M 查询评测耗时 | 采样评测 + 完整评测双轨 |
| 继承的随机划分导致时间戳重叠 | threat-to-validity 主动披露,对所有方法一致 |
